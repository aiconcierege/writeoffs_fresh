# Authorized scope and shared customer work certification

## Contract

The selected start and existing commercial coverage authority jointly bound active bookkeeping. Source evidence is retained outside that interval; upload and provider history cannot enlarge it. Historical Catch-up exists only when an earlier-than-included start was explicitly selected and covered. Without that selection, the included prior month is Current, not Catch-up.

Home, Check-in, question eligibility, active ledger reads and working reports use the same scope. Shared account prerequisites count once. Explicit transaction corrections remain available separately from pending customer work. Read paths do not create bookkeeping facts.

## Real dedicated-staging certification

Isolated marked synthetic customers completed normal onboarding, actual UI document upload, normal workers and applicable UI answers. No Rick accounts were used as mutable fixtures. Historical authorization used synthetic grandfathered commercial coverage followed by the normal start-selection API; this does not certify a Stripe payment flow.

## Additional defects found during certification

- Trusted statement ingestion temporarily adopts owner claims without interactive MFA. Internal scope validation now uses a private trusted predicate after existing ownership/lease guards, rather than an interactive customer RPC.
- Scope expansion needed visible, bounded, resumable reassessment and a scheduled-worker handoff. The dedicated queue now supplies both, preserving job idempotency.
- Question-answer eligibility must derive the actual membership plan when omitted, rather than defaulting business members to expense-only questions.
- Explicit special-transaction correction links must remain available even after an item leaves the ordinary question queue.
